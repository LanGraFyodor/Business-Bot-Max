# Accounting QA & Mock Runner — Сервис автоматизации тестирования учетных систем (Ozon Tech)

Микросервис на **Python 3.11+ / FastAPI**, спроектированный для автоматизированного контроля качества, сбора метрик и сквозного тестирования интеграций с учетными системами (**1C**, бухгалтерия, казначейство) и внешними REST API.

---

## 1. Архитектурное назначение и связь с Ozon Tech

В направлении **«Разработка учетных систем» Ozon Tech** ключевыми задачами являются:
- Разработка сервисов и инструментов на Python для автоматизации тестирования и сбора метрик;
- Парсинг и генерация учетных отчетов (План-факт, ДДС, расчетные ведомости, акты сверки);
- Контроль качества и отказоустойчивости API: проверка идемпотентности, обработка сбоев сети, поиск нестабильных (flaky) тестов;
- Внедрение ИИ-ассистентов в ежедневный рабочий процесс.

Данный микросервис реализует паттерн **Sidecar / Сателлитный сервис QA**, работающий независимо от основного Go-сервера Docspace:
- Основной Go-сервер обслуживает ядро системы на `:8080`.
- Python QA-сервис запускается на `:8081`, генерирует реалистичные учетные проводки 1С и стресс-тестирует контракты интеграции.

## 2. Ключевые возможности

### А. Генерация реалистичных данных 1С (`/api/v1/generator/`)
Генератор синтезирует бухгалтерские и финансовые отчеты в формате CSV с корректным разделителем `;`, кодировкой UTF-8 и расчетом SHA-256 контрольных сумм:
1. **План-Факт анализ (`plan_fact`):** плановые vs фактические затраты отделов Ozon, процент выполнения, дельта отклонений.
2. **Движение денежных средств (`cash_flow`):** статьи ДДС, приход/расход, корреспондирующие счета (51.01, 51.02), чистый денежный поток.
3. **Расчетная ведомость по зарплате (`payroll`):** табельные номера, оклады, удержание НДФЛ 13%, суммы к выплате.
4. **Акт сверки расчетов 1С (`reconciliation`):** первичные документы, дебет, кредит, плавающее сальдо.
5. **Инъекция аномалий (`inject_anomaly=true`):** генерация намеренно некорректных данных (критический перерасход >85%, отрицательные суммы в ДДС) для проверки валидаторов принимающей стороны.

### Б. Комплексный сьют автотестов (`/api/v1/qa/run-suite`)
Сервис запускает батарею автоматических тестов против целевого REST API:
* **TC-01-HEALTH:** Проверка доступности Healthcheck (`GET /api/health` -> 200, `ok: true`).
* **TC-02-SECURITY:** Защита от неавторизованного доступа (`GET /api/integrations/channels` без токена -> строго 401 Unauthorized).
* **TC-03-DISCOVERY:** Обнаружение учетных каналов команды по Bearer-токену (`GET /api/integrations/channels` -> 200, массив каналов).
* **TC-04-INGESTION:** Сквозная загрузка бинарного отчета 1С через POST-стрим с флагом `review=1` (`POST /api/integrations/documents` -> 201 Created).
* **TC-05-IDEMPOTENCY:** Контроль идемпотентности по `externalId` — повторная отправка идентичного отчета не создает дубликат и возвращает 200 OK с существующим ID документа.
* **TC-06-TRACKING:** Снятие статуса согласования и замечаний руководителя по `externalId` (`GET /api/integrations/documents?externalId=...` -> 200 OK).
* **TC-07-FLAKY-BENCHMARK:** Серия повторных вызовов с замером джиттера задержки (разброс min/max, среднее время, детекция периодических таймаутов).

### В. Метрики и история (`/api/v1/qa/history`, `/api/v1/qa/metrics`)
* Ведение циклического буфера последних прогонов.
* Расчет интегрального процента успешности (Success Rate %) и среднего времени отклика.

## 3. Быстрый запуск

### Вариант 1. Локально через Python (без Docker)

```powershell
# Переходим в директорию сервиса
cd d:\Hackaton\MAX\services\accounting_qa

# Запуск приложения на порту 8081
python -m uvicorn app.main:app --host 127.0.0.1 --port 8081 --reload
```

После запуска интерактивная документация Swagger доступна по адресу:
👉 **[http://127.0.0.1:8081/docs](http://127.0.0.1:8081/docs)**

### Вариант 2. Запуск через Docker Compose

Сервис включен в общий [compose.yaml](../../compose.yaml):
```powershell
docker compose up accounting_qa --build -d
```

### Вариант 3. Запуск unit-тестов сервиса

```powershell
cd d:\Hackaton\MAX\services\accounting_qa
python -m pytest -v tests/
```

## 4. Спецификация API (эндпоинты)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/docs` | Интерактивный Swagger UI |
| `GET` | `/api/v1/health` | Проверка состояния сервиса тестирования |
| `POST` | `/api/v1/generator/report` | Генерация JSON-структуры синтетического отчета 1С |
| `GET` | `/api/v1/generator/sample-csv` | Скачивание сгенерированного файла CSV |
| `POST` | `/api/v1/qa/run-suite` | Запуск полного цикла интеграционных тестов |
| `GET` | `/api/v1/qa/history` | История недавних запусков |
| `GET` | `/api/v1/qa/metrics` | Метрики стабильности и качества API |
