# Скриншоты для презентации

Это кадры **работающих локальных веб-интерфейсов**, снятые в Microsoft Edge при открытом проекте на `http://127.0.0.1:8080`. Они показывают тот же React UI, который предназначен для мини-приложений MAX. Кадры **не подтверждают**, что экраны уже открыты внутри MAX: для такого доказательства после публикации по HTTPS сделайте отдельный снимок с телефона в клиенте MAX.

Снимки мобильных экранов имеют размер 390 × 844 CSS px при двойной плотности пикселей. Десктопные — 1440 × 900 px. Данные компании и бизнес-примеры синтетические. Перед повторной съёмкой сохраните нужное состояние демо; скрипт только открывает страницы и не отправляет изменения на сервер.

| Файл | Что видно | Для какого тезиса |
|---|---|---|
| [01 — единый вход](01-one-bot-two-apps-mobile.png) | Два самостоятельных приложения | «Два инструмента — один бот»; это локальная страница выбора, не чат MAX |
| [02 — документы](02-documents-mobile.png) | Каналы, файлы, версии, статусы | Рабочее пространство команды на телефоне |
| [03 — очередь](03-review-queue-mobile.png) | Документы на согласовании | Руководитель видит накопившиеся решения |
| [04 — решение](04-document-decision-mobile.png) | Читаемый DOCX, скачивание, новая версия, согласовать/вернуть | Основной пользовательский сценарий |
| [05 — системы](05-integrations-desktop.png) | 1С, Битрикс24, amoCRM и API как разделы отчётов | Масштаб: документы из внешних систем |

**Самая сильная последовательность для короткой защиты:** 01 → 02 → 04 → 07 → 05 → 08 → 10. Для технического слайда добавьте после публикации реальный скриншот двух кнопок **из чата бота MAX**; его пока нет в этой папке.

Повторить съёмку без изменения данных:

```powershell
node web/capture-presentation.mjs
```

По умолчанию скрипт использует `http://127.0.0.1:8080`. Для другого адреса задайте `PRESENTATION_BASE_URL`. Перед запуском должны работать локальный сервер и Edge; Node-зависимости ставятся через `npm --prefix web ci`.
