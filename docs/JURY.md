## Вход в приложение и код приглашения — разные вещи

В Docspace нет отдельного логина и пароля: откройте мини-приложение кнопкой «Документы» в боте, и MAX передаст подписанные данные вашего аккаунта. Сервер проверит их и определит пользователя. Токен Bot API пользователям и проверяющим не нужен: он хранится только на сервере.

Код приглашения нужен для вступления в компанию и назначения роли. Самый простой путь — один раз отправить боту `/join КОД`, затем открыть «Документы». При следующих открытиях повторно вводить код не требуется, пока членство и срок доступа действуют.

Если видите «Откройте приложение из MAX: данные входа недействительны», приложение не получило действительные данные аккаунта. При открытии HTTPS-ссылки в обычном браузере это ожидаемо. Откройте бота и запустите приложение его кнопкой после привязки URL организаторами. Если ошибка появляется именно внутри MAX, закройте мини-приложение и откройте заново; если повторяется, сообщите команде — нужно проверить передачу и проверку данных входа. Пригласительный код не заменяет авторизацию MAX.

## Как получить роль

Оба кода доступны в [отдельном файле с кодами и ссылками](REVIEWER-ACCESS.md). Выберите роль и скопируйте готовую команду.

1. Откройте указанного бота под своим аккаунтом MAX и нажмите «Начать» либо отправьте `/start`.
2. Отправьте `/join ПОЛУЧЕННЫЙ_КОД`.
3. Дождитесь ответа о присоединении к семи тестовым командам и назначенной роли.
4. Нажмите кнопку «Документы». Если мини-приложение уже было открыто, закройте и откройте его снова.
5. Выберите «Орбита» для базового сценария, «Финансовый блок» для отчётов 1С либо другой отдел.

Вступление выполняется через `/join`, после подтверждения откройте приложение кнопкой бота. Для Бизнес-навигатора членство в команде не нужно.

**Один общий код рассчитан на 100 разных аккаунтов.** Повторный ввод своим аккаунтом не создаёт дубль и не расходует дополнительные места. Два разных кода дают две разные роли. Уже выданную роль кодом другой роли изменить нельзя: её меняет руководитель; для одновременного теста используйте два MAX-аккаунта.

Общие коды не отменяют обычные приглашения: руководитель по-прежнему может выдать одноразовое приглашение на 7 дней, в том числе адресно для определённого MAX ID. Общий код также можно отозвать в «Команды и роли → Орбита → Приглашения и доступ».

## Срок и данные

Тестовая копия доступна до **31 октября 2026, 00:20:37 МСК** (30 октября, 21:20:37 UTC). После этого сервер прекращает выдавать доступ к семи тестовым командам, файлам и их интеграционным ключам. Файлы не удаляются автоматически. Срок не относится к отдельно созданным пользователями собственным командам.

Исходный набор скопирован: **7 команд, 40 каналов, 194 документа, 199 файлов версий**. Старые люди и документы — синтетические примеры. Новые проверяющие появляются с настоящим MAX ID. Синтетические профили не получают сообщения бота. Локальное демо `data/demo` сохранено.

Руководитель в тестовой копии получает управление всеми семью командами. Сотрудник читает документы, обсуждает их, загружает собственные файлы и направляет их на согласование. Для показа разных ролей одного человека в разных командах руководитель может изменить членство отдельно в нужном отделе.

## Основной сценарий на двух телефонах

1. Телефон А вступает по коду сотрудника, телефон Б — по коду руководителя.
2. Сотрудник в «Орбита» загружает **свой новый** PDF/DOCX/XLSX/CSV и отправляет на согласование.
3. Руководитель получает сообщение бота, открывает очередь проверки и документ.
4. Руководитель скачивает файл, возвращает с комментарием либо согласует.
5. Сотрудник получает сообщение о решении. При возврате добавляет новую версию и отправляет снова.
6. На согласованном документе дочернего отдела руководитель может проверить передачу на следующий уровень.
7. В «Отчёты» проверьте разделы 1С/CRM и загрузку файла. Подключения к настоящей базе 1С в наборе нет.
8. Вторая кнопка бота открывает Бизнес-навигатор: поиск → источник → план запуска.

Сотрудник не может редактировать чужой демонстрационный файл: он проверяет загрузку версий на собственном документе. Уведомление автору старого синтетического документа не отправляется; для уведомлений используйте новый файл реального тестировщика.
