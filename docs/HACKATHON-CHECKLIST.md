## Что показать по критериям оценки

Онлайн-этап: продуктовая оценка — 40%, техническая — 60%. Вес внутри продуктовой оценки: масштабирование 35%, пользовательская ценность 25%, UX/UI 20%, целостность 15%, презентация 5%.

| Критерий | Наше доказательство / сценарий |
|---|---|
| Масштабирование | От одной команды к отделам: сохраняются версии, согласование и роли; адаптируются структура, источники отчётов и правила. Для промышленной нагрузки нужны БД, хранилище файлов и эксплуатация |
| Пользовательская ценность | Вместо пересылок и поиска актуального файла — карточка с версиями, обсуждением и решением. Экономия времени пока гипотеза, интервью и измерения не заявлены |
| UX/UI | С телефона: войти → загрузить → отправить → получить решение. В README показаны реальные экраны |
| Целостность | Главный сценарий — документ до решения; справочник — самостоятельный дополнительный инструмент для начала бизнеса |
| Техническая работоспособность | Настоящие файлы, серверная проверка прав, повторные версии, сохранение состояния, API и уведомления. Сценарий повторить двумя реальными аккаунтами |
| Платформенный бонус +0,15 | Не заявляем как гарантированный: базовая авторизация, кнопки и наличие API сами по себе бонус не обеспечивают; требуется доказать дополнительную возможность MAX и её ценность |

## Последние действия перед сдачей

1. Пройти [сценарий двумя аккаунтами](JURY.md) в мобильном и веб-клиенте MAX; проверить скачивание, новую версию, решение, уведомление и повторный вход.
2. Для API: руководитель создаёт ключ интеграции в «Отчёты» → настройки обмена нужной команды. Передать ключ организаторам через закрытое поле или служебный слайд; использовать его как `DOCSPACE_TEST_INTEGRATION_TOKEN`. Приглашение `/join` не является API-ключом.
3. Проверить API по DATA-API.yaml: health, список каналов, импорт CSV, чтение статуса и отказ без ключа. Формальный валидатор организаторов в проекте не предоставлен.
4. Приложить финальную PDF-презентацию. На первом слайде дать ссылки, доступы и сценарий; далее — состав команды, проблему, решение, эффект, архитектуру, данные, масштабирование, ограничения и источники. Не публиковать служебные секреты в открытой версии презентации.
5. Приложить архив и его контрольную сумму из одной сборки. По FAQ сдача — до 30 сентября, 12:00 МСК, через личный кабинет; после дедлайна переданная версия фиксируется.
6. Сохранить доступность сервера весь период проверки. Если проверка продлится после срока тестовых ролей, заранее согласовать продление доступа.

По критериям допуска кейса отсутствие презентации или недоступность основного сценария в MAX препятствуют допуску. Красивый README не заменяет эти два условия.
