# Спецификация требований к данным (Data Requirements)

Проект: «Конструктор бизнеса и агенты-помощники в MAX»  
Целевая аудитория: Самозанятые (НПД), Индивидуальные предприниматели (ИП), Малый бизнес (ООО, микропредприятия).  
Трек хакатона: «Эффективный бизнес» (Цифровая платформа MAX).  
Версия документа: 1.0  

---

## 1. Введение и бизнес-контекст

### 1.1. Назначение системы
Решение объединяет два взаимосвязанных контура:
1. Конструктор витрины в мессенджере MAX: развертывание каталога товаров и услуг, управление остатками и прием заказов.
2. Интеллектуальный помощник: навигация по правовым нормам, расчет налогов, проверка обязательной маркировки, интерактивные чек-листы и мониторинг финансовой устойчивости.

### 1.2. Особенности целевых сегментов

| Сегмент | Ключевые ограничения и специфика | Критичные данные для сценариев |
|---|---|---|
| Самозанятый (НПД) | Лимит дохода 2.4 млн рублей в год, запрет на перепродажу чужих товаров, запрет на наем сотрудников по трудовому договору, ставки 4% (физлица) и 6% (юрлица). | Лимит выручки, признак собственного производства, нулевой штат. |
| ИП (УСН, Патент, АУСН) | Вправе нанимать персонал и перепродавать товары. Лимит УСН до 450 млн рублей. Обязательны фиксированные взносы за себя (53 658 рублей за 2026 год) и онлайн-кассы по 54-ФЗ. | Доходы, расходы, ставка УСН (6% или 5-15% в регионах), штат, ФОТ, код ОКВЭД 2. |
| Малый бизнес (ООО) | Юридическое лицо с обязательным расчетным счетом, директором и бухучетом. Повышенная ответственность по КоАП РФ. | ОКВЭД, регион регистрации, количество сотрудников, прогноз выручки, налоги, вывески. |

## 2. Принципы работы с данными

В системе действует строгая таксономия:

```
┌────────────────────────────────────────────────────────────────────────┐
│                          ТАКСОНОМИЯ ДАННЫХ                             │
├─────────────────┬─────────────────┬──────────────────┬─────────────────┤
│  ФАКТЫ (НПА)    │    РАСЧЕТЫ      │  РЕКОМЕНДАЦИИ    │    МОДЕЛЬНЫЕ    │
│                 │                 │                  │     ДАННЫЕ      │
│ Первоисточники, │ Детерминирован- │ Подсказки агента,│ Синтетические   │
│ статьи законов, │ ные формулы,    │ чек-листы, риск- │ моки внешних    │
│ реестры ФНС     │ налоги, маржа   │ профилирование   │ API             │
└─────────────────┴─────────────────┴──────────────────┴─────────────────┘
```

1. Приоритет первоисточника (Single Source of Truth). Каждая норма права или ставка привязана к официальному акту на pravo.gov.ru или nalog.gov.ru, статье закона и дате актуальности редакции.
2. Прозрачность происхождения. Интерфейс разделяет цитату закона (факт), результат калькулятора (расчет) и совет ассистента (рекомендация).
3. Явные допущения. Все расчеты калькулятора сопровождаются списком допущений (примененная региональная ставка, базовая сумма взносов, исключение НДС).
4. Маркировка модельных данных. Интеграции, не имеющие открытого государственного API (согласование вывески в муниципалитете, эмуляция эквайринга), снабжены признаком is_mocked_data = true.
5. Принцип Zero PII по 152-ФЗ. Отказ от сбора избыточных персональных данных. Паспортные данные, номера банковских карт и СНИЛС в базе данных не хранятся. Идентификация выполняется через технический max_user_id.

## 3. Спецификация доменов данных

Система разделена на 4 изолированных домена:
- Profile Domain (пользователи и карточки бизнеса).
- Commerce Domain (витрины, каталоги и заказы).
- Finance Domain (налоги, взносы, точка безубыточности).
- Legal Domain (первоисточники НПА и требования).

### Домен профилей

#### Сущность `users` (Пользователи платформы MAX)
Хранит профиль пользователя мессенджера MAX.
- id (UUID, PK): внутренний идентификатор.
- max_user_id (VARCHAR(128), UNIQUE, NOT NULL): идентификатор в платформе MAX.
- username (VARCHAR(64), NULL): никнейм в MAX.
- created_at, last_active_at (TIMESTAMPTZ): отметки времени.

#### Сущность `business_profiles` (Карточка бизнеса)
Параметры бизнеса, используемые конструктором витрины, калькулятором и правовыми агентами.
- id (UUID, PK).
- user_id (UUID, FK к users.id, NOT NULL).
- legal_form (VARCHAR(20), NOT NULL): self_employed, ip, ooo.
- business_name (VARCHAR(255), NOT NULL): коммерческое наименование бизнеса.
- inn (VARCHAR(12)): ИНН (10 цифр для ООО, 12 цифр для ИП, NULL для самозанятого).
- okved_code (VARCHAR(16), NOT NULL): основной код по ОКВЭД 2.
- region_code (VARCHAR(10), NOT NULL): код субъекта РФ (77 для Москвы, 16 для Татарстана).
- city (VARCHAR(128), NOT NULL): город ведения деятельности.
- tax_regime_code (VARCHAR(32), NOT NULL): выбранный налоговый режим.
- has_employees (BOOLEAN, NOT NULL, DEFAULT false): признак наемных сотрудников.
- employee_count (INTEGER, NOT NULL, DEFAULT 0): число сотрудников (для НПД строго 0).
- monthly_revenue_est, monthly_expenses_est (NUMERIC(14,2), NOT NULL, DEFAULT 0).
- status (VARCHAR(20), NOT NULL): draft, active, suspended.
- created_at, updated_at (TIMESTAMPTZ).

---

### Домен торговли

#### Сущность `stores` (Интернет-магазин в MAX)
Настройки витрины, открываемой покупателями в мессенджере.
- id (UUID, PK).
- business_profile_id (UUID, FK к business_profiles.id, NOT NULL).
- slug (VARCHAR(64), UNIQUE, NOT NULL): ссылка на витрину в MAX.
- title (VARCHAR(128), NOT NULL): название магазина.
- description (TEXT): описание условий и ссылка на политику конфиденциальности.
- logo_url, banner_url (VARCHAR(512)): медиа-файлы.
- contact_phone (VARCHAR(32)): контактный телефон.
- pickup_address (TEXT): адрес точки самовывоза.
- delivery_enabled (BOOLEAN, DEFAULT false): признак курьерской доставки.
- delivery_terms (TEXT): условия и зоны доставки.
- delivery_min_amount, delivery_fee (NUMERIC(12,2)): порог и стоимость доставки.
- is_published (BOOLEAN, DEFAULT false): видимость в каталоге MAX.
- created_at, updated_at (TIMESTAMPTZ).

#### Сущность `product_categories`
- id (BIGSERIAL, PK).
- store_id (UUID, FK к stores.id, NOT NULL).
- name (VARCHAR(128), NOT NULL): название рубрики.
- sort_order (INTEGER, DEFAULT 0): порядок сортировки.

#### Сущность `products` (Товары и услуги)
- id (UUID, PK).
- store_id (UUID, FK к stores.id, NOT NULL).
- category_id (BIGINT, FK к product_categories.id, NULL).
- type (VARCHAR(20), NOT NULL): good (товар) или service (услуга).
- name (VARCHAR(255), NOT NULL): название позиции.
- description (TEXT): описание, состав, свойства.
- price (NUMERIC(12,2), NOT NULL, CHECK (price >= 0)): цена в рублях.
- currency (VARCHAR(3), DEFAULT 'RUB').
- unit (VARCHAR(20), DEFAULT 'шт'): единица измерения.
- is_in_stock (BOOLEAN, DEFAULT true): наличие на складе.
- stock_quantity (INTEGER, DEFAULT 0, CHECK (stock_quantity >= 0)).
- image_url (VARCHAR(512)): фото карточки.
- requires_marking (BOOLEAN, DEFAULT false): признак маркировки в Честный ЗНАК.
- status (VARCHAR(20), DEFAULT 'active'): active, archived.

#### Сущности `orders` и `order_items`
- orders фиксирует номер заказа (order_number), идентификатор покупателя (customer_max_user_id), контактное имя и телефон, способ доставки, итоговую сумму и статус (new, confirmed, in_progress, delivered, cancelled).
- order_items фиксирует снимок цены и названия (product_name_snapshot, unit_price_snapshot) на момент покупки. При удалении товара из каталога позиции чека сохраняют историческую целостность.

### Домен финансов и налогов

#### Сущность `tax_regimes`
Справочник режимов налогообложения РФ (актуальность 2026 года).
- code (VARCHAR(32), PK): npd, usn_income, usn_income_expense, ausn_income, ausn_income_expense, psn, osno.
- name, short_name: официальное и краткое название.
- allowed_legal_forms (VARCHAR(20)[]): допустимые формы бизнеса.
- max_annual_revenue (NUMERIC(14,2)): лимит выручки (2.4 млн руб. для НПД, 450 млн руб. для УСН).
- max_employees (INTEGER): лимит численности штата.
- base_tax_rate_percent (NUMERIC(5,2)): базовая ставка.
- fixed_insurance_required (BOOLEAN): обязанность уплаты фиксированных взносов ИП за себя.
- source_id (VARCHAR(64), FK к legal_sources.id).

#### Сущность `tax_calculations`
История и результаты расчетов налогового калькулятора.
- id (UUID, PK).
- business_profile_id (UUID, FK к business_profiles.id, NOT NULL).
- input_parameters (JSONB, NOT NULL): снимок исходных данных (выручка, расходы, число сотрудников, регион).
- results_comparison (JSONB, NOT NULL): сравнение налогов по режимам с указанием причин неприменимости.
- recommended_regime_code (VARCHAR(32)): математически выгодный режим.
- estimated_annual_tax (NUMERIC(14,2)): расчетный годовой налог.
- estimated_annual_insurance (NUMERIC(14,2)): сумма страховых взносов.
- assumptions (TEXT[], NOT NULL): допущения и правовые оговорки к расчету.

#### Сущность `financial_health_assessments`
Оценка жизнеспособности бизнеса:
- margin_percent: маржинальность бизнеса в процентах.
- break_even_point: точка безубыточности в рублях.
- safety_margin_percent: запас финансовой прочности в процентах.
- cash_gap_risk_level: риск кассового разрыва (LOW, MEDIUM, HIGH).
- verdict: итоговый статус (SUSTAINABLE, AT_RISK, CRITICAL).
- recommendations (JSONB): пошаговые меры по оптимизации расходов.

### Домен права и регуляторики

#### Сущность `legal_sources`
Реестр первоисточников нормативно-правовых актов РФ:
- id (VARCHAR(64), PK): fz_422_npd, nk_rf_usn, fz_54_kkt, fz_152_pdn, rasp_792_marking.
- name: официальное название документа.
- official_url: ссылка на публикацию на pravo.gov.ru или ведомственном портале.
- publisher: орган государственной власти (ФНС России, Минфин РФ, Правительство РФ).
- source_type: federal_law, code_rf, gov_decree, municipal_act.
- checksum_sha256: контрольная сумма исходного файла текста.
- effective_date: дата вступления в силу действующей редакции.

#### Сущность `business_requirements`
Атомарные правовые нормы, привязанные к форме бизнеса, региону и ОКВЭД:
- id (BIGSERIAL, PK).
- source_id (VARCHAR(64), FK к legal_sources.id, NOT NULL).
- category: registration, taxes, kkt_receipts, signboards, personal_data, labeling, sanitary.
- title: короткая формулировка сути правила.
- summary: описание простым языком для предпринимателя.
- legal_citation: точная статья закона (например, «п. 8 ч. 2 ст. 4 Федерального закона № 422-ФЗ»).
- applies_to_legal_forms (VARCHAR(20)[]): массив применимости (самозанятый, ИП, ООО).
- applies_to_okved_prefixes (VARCHAR(16)[]): фильтр по кодам отраслей.
- region_code: код региона для местных актов (для федеральных норм NULL).
- penalty_risk_description: статьи КоАП РФ и суммы штрафов.
- action_plan (JSONB): пошаговый алгоритм действий со сроками и бланками.
- is_simulated_in_mvp (BOOLEAN): признак демонстрационной модели в рамках MVP.

#### Сущность `signboard_regulations`
Модельный справочник правил размещения информационных вывесок по городам. Содержит предельные габариты, требования к документам и признак is_mocked_data = true.

## 4. Контроль качества данных (Data Quality Constraints)

| Код | Объект валидации | Условие проверки | Поведение системы при нарушении |
|---|---|---|---|
| DQ-01 | business_profiles | legal_form = 'self_employed' влечет monthly_revenue_est * 12 <= 2 400 000 | Блокировка сохранения профиля НПД, рекомендация перехода на ИП на УСН. |
| DQ-02 | business_profiles | legal_form = 'self_employed' влечет employee_count = 0 и has_employees = false | Отклонение сохранения: самозанятый не вправе нанимать персонал по ТК РФ. |
| DQ-03 | products, business_profiles | price >= 0, revenue >= 0, expenses >= 0, stock_quantity >= 0 | Ошибка валидации HTTP 422 с указанием некорректного поля. |
| DQ-04 | business_profiles | Регулярное выражение ИНН: 10 цифр для ООО, 12 цифр для ИП, NULL для НПД | Отметка записи как невалидной с логированием в WARN. |
| DQ-05 | business_profiles | region_code обязан существовать в таблице regions | Блокировка сохранения профиля с несуществующим кодом субъекта РФ. |
| DQ-06 | products, business_profiles | При ОКВЭД 47.71 (одежда) или 47.72 (обувь) товар требует requires_marking = true | Автоматическая установка флага маркировки и предупреждение в UI. |

## 5. Внешние интеграции

Платформа MAX (Bot API и Bridge). Доставка сообщений, UI мини-приложений, контекст диалога. Авторизация идет через токен бота и max_user_id.

ФНС России. Официальные ставки НПД, УСН и суммы фиксированных взносов ИП зафиксированы в справочниках tax_regimes и tax_regional_rates.

ГИС МТ «Честный ЗНАК». Контроль обязательности цифровой маркировки Data Matrix для обувных и текстильных товарных групп через валидатор DQ-06.

Согласование вывесок. Муниципальная услуга Комитетов архитектуры смоделирована на базе Постановления Москвы № 902-ПП с признаком is_mocked_data = true.

Платежи. Оформление заказов в витрине выполняется со статусом подтверждения без сохранения данных банковских карт.

## 6. Тестовые профили и воспроизводимость

В seeds/test_dataset.json подготовлены 10 воспроизводимых сценариев (включая кондитерскую, IT-студию, магазин одежды с маркировкой, кофейню, обувной ритейл и маркетинговое агентство).

Краевые случаи датасета:
1. Порог НПД (студия дизайна интерьеров Zaripova Design): доход 195 000 рублей в месяц дает 2.34 млн рублей в год (97.5% от лимита 2.4 млн рублей). Система сохраняет статус устойчивости, но выводит предупреждение о скорой утрате права на НПД и предлагает переход на ИП на УСН 6%.
2. Кассовый разрыв (сувенирная лавка Подарки Казани): выручка 180 000 рублей при расходах 240 000 рублей. Чистый убыток 60 000 рублей в месяц, запас прочности минус 125%, статус CRITICAL.

## 7. Модель масштабирования

Архитектура строго разделяет неизменяемое ядро и адаптивные модули:

Ядро (неизменное):
- Модель сущностей пользователей, витрин, товаров, категорий и заказов.
- Движок расчета Unit-экономики и точки безубыточности.
- Реляционная схема связи правовых требований с первоисточниками.
- Механизм разграничения прав и изоляции данных.

Переменная часть (адаптивная):
- Сетка региональных налоговых ставок в таблице tax_regional_rates.
- Муниципальные регламенты вывесок в таблице signboard_regulations.
- Отраслевые базы кодов ОКВЭД 2 и признаков маркировки.
- Векторные эмбеддинги требований для семантического поиска в pgvector при расширении базы знаний.
