# Архитектура и руководство по ELT/ETL-пайплайну (Data Pipeline)
## Проект: «Конструктор бизнеса и экосистема агентов-помощников в MAX»
**Каталог кода:** `etl/`  
**Контейнер Docker:** `max_business_etl` в [compose.yaml](file:///d:/Hackaton/MAX/compose.yaml)  
**Единая команда запуска:** `docker compose run --rm etl`

---

## 1. Выполнение обязательных требований

| Требование | Как реализовано в пайплайне |
|---|---|
| **1. Идемпотентность** | Все SQL-операции используют синтаксис `INSERT ... ON CONFLICT (...) DO UPDATE`. Повторный запуск (хоть 100 раз) не создает дубликатов строк и не нарушает первичные/внешние ключи. |
| **2. Информативные логи** | Модуль `etl/logger.py` выводит цветные логи в реальном времени с таймстемпами, этапами, количеством считанных/записанных строк и итоговой сводной таблицей метрик. |
| **3. Ошибки валидации не роняют всё молча** | Модуль `etl/validator.py` изолирует каждую запись. При нарушении бизнес-правил (DQ-01, DQ-02, отрицательная цена, битый FK) в консоль выводится подробный `[WARNING]` с указанием ID строки, поля и ошибочного значения, а валидные записи продолжают обрабатываться. |
| **4. Запуск из одной строки** | **`docker compose run --rm etl`** (или `python -m etl.run_pipeline`). |
| **5. Полный запуск в Docker** | В [compose.yaml](file:///d:/Hackaton/MAX/compose.yaml) добавлен легковесный сервис `etl` на базе `python:3.11-slim`, запускающийся после перехода базы `db` в статус `healthy`. |
| **6. Безопасность и отсутствие секретов** | Конфигурация `etl/config.py` читает строку подключения исключительно из переменной окружения `DATABASE_URL` (или шаблона `.env.example`). Никаких паролей и токенов в коде нет. |

## 2. Архитектура и этапы ETL-процесса

```
┌────────────────────────────────────────────────────────────────────────┐
│                        АРХИТЕКТУРА ETL-ПАЙПЛАЙНА                       │
├─────────────────┬──────────────────┬─────────────────┬─────────────────┤
│  1. EXTRACT     │   2. VALIDATE    │  3. TRANSFORM   │    4. LOAD      │
│                 │                  │                 │                 │
│ Чтение JSON из  │ Проверка бизнес- │ Форматирование  │ Идемпотентный   │
│ data/reference/ │ правил (DQ-01..  │ типов, упаковка │ UPSERT в        │
│ и data/seeds/   │ DQ-06), схемы    │ JSONB, UUID     │ PostgreSQL 15   │
└─────────────────┴──────────────────┴─────────────────┴─────────────────┘
```

### Этап 0: Проверка доступности СУБД (Handshake)
Проверяет сетевую доступность базы данных. Если СУБД еще стартует в контейнере, пайплайн выполняет до 15 повторных попыток с экспоненциальной задержкой, исключая падение по таймауту.

### Этап 1: Правовые первоисточники и требования (`legal_loader.py`)
1. Загружает реестр 14 первоисточников `legal_sources` (ФНС, Минфин, Роспотребнадзор, Правительство РФ).
2. Загружает 17 прикладных бизнес-требований `business_requirements` с проверкой существования ссылки на первоисточник (`source_id`), допустимости категории и валидности штрафов/санкций.

### Этап 2: Нормативно-справочная информация (`reference_loader.py`)
1. Загружает 7 налоговых режимов РФ (`tax_regimes`) с лимитами выручки и ставками на 2026 год.
2. Загружает дифференцированные региональные ставки УСН (`tax_regional_rates`) для Татарстана (7%), Москвы (10%/15%), Санкт-Петербурга (7%) и др.
3. Загружает регламенты вывесок по городам (`signboard_regulations`).
4. Загружает шаблоны дорожных карт запуска (`checklists`) и 13 прикладных пунктов (`checklist_items`).

### Этап 3: Эталонные синтетические данные для жюри (`seed_loader.py`)
1. Пользователи MAX: профили предпринимателей (Анна, Михаил, Артур).
2. Бизнес-профили:
   - Самозанятый кондитер «Сладкий Лис» (Москва, НПД, выручка 95 тыс. руб./мес).
   - ИП Магазин одежды «Север» (Татарстан, УСН 7%, 2 сотрудника, маркировка).
   - Малый бизнес Кофейня «Зерно & Толк» (ООО, 5 сотрудников, общепит).
3. Витрины и интернет-магазины в MAX (`stores`).
4. Каталог товаров с ценами, остатками и признаками маркировки «Честный ЗНАК» (`products`).
5. Тестовые клиентские заказы и состав корзины (`orders`, `order_items`).

### Этап 4: Smoke-проверка фактического наполнения таблиц
Выполняет проверочные агрегирующие SQL-запросы `COUNT(*)` к 13 таблицам базы данных и выводит фактическое количество строк.

## 3. Команды для запуска

### Вариант А: Запуск в Docker (Основной регламент хакатона)

Одной командой (сборка контейнера + выполнение ETL):
```bash
docker compose run --rm etl
```

Либо запуск всего окружения целиком:
```bash
docker compose up -d db
docker compose up --build etl
```

---

### Вариант Б: Локальный запуск (если запущен локальный Python и Postgres)

1. Установите минимальную зависимость:
   ```bash
   pip install -r etl/requirements.txt
   ```
2. Запустите пайплайн:
   ```bash
   python -m etl.run_pipeline
   ```
   *(или через скрипт `powershell -File etl/run_local.ps1`)*
